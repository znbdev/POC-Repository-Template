# 积分卡管理 — GitHub Pages 部署过程记录

## 背景

Points Card Manager 是一个 Vite + React 前端项目，需要通过 GitHub Actions 自动部署到 GitHub Pages。

## 步骤记录

### 1. 创建部署工作流

创建 `.github/workflows/deploy.yml`，使用 `actions/upload-pages-artifact@v3` + `actions/deploy-pages@v4` 组合。

工作流触发条件：
- 推送 `main` 分支，且路径匹配 `points-card-manager/**` 或 `.github/workflows/deploy.yml`
- 支持手动触发（`workflow_dispatch`）

### 2. 创建一键部署脚本

创建 `deploy.sh`，封装 `git add` → `git commit` → `git push` 流程。

### 3. 首次部署失败

**问题：** GitHub Actions 执行到 `deploy-pages` 步骤时报错：

```
Error: Creating Pages deployment failed
HttpError: Not Found (404)
Ensure GitHub Pages has been enabled
```

**原因：** 仓库的 GitHub Pages 功能未开启。

### 4. 启用 GitHub Pages

有两种方式：

#### 方式 A：Web 界面（手动）
仓库 Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**

#### 方式 B：GitHub CLI（推荐，一次命令）
```bash
gh api -X POST /repos/<owner>/<repo>/pages \
  --input - <<'EOF'
{
  "build_type": "workflow"
}
EOF
```

我们使用了方式 B。

### 5. 验证 Pages 已启用

```bash
gh api /repos/<owner>/<repo>/pages
```

返回 `build_type: "workflow"` 即表示已启用 Actions 模式。

### 6. 重新运行部署

```bash
gh run rerun <run-id>
```

部署成功，访问 `https://<owner>.github.io/<repo>/` 返回 HTTP 200。

## 关键教训

| 问题 | 解决 |
| --- | --- |
| Pages 未启用时 `actions/deploy-pages` 返回 404 | 需先在 Settings 或通过 API 启用 Pages |
| 刚启用 Pages 后立即运行可能因传播延迟失败 | 启用后重跑一次即可 |
| `gh api` 可完全替代 Web 界面操作 | 适用于自动化/远程场景 |

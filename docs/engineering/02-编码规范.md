# 编码规范

> 通用原则适用于所有技术栈；各语言细则见对应小节，团队按项目技术栈取用。

## 通用原则

- 避免魔法值：重复出现两次以上的字面量提取为命名常量
- 提前返回（early return），减少 if 嵌套层级
- 错误必须显式处理，禁止静默吞异常 / 空 catch
- 公共函数写文档注释：做什么、参数、返回值、可能抛出的异常
- 提交前跑格式化与 lint（工具见各语言小节），与 CI 门禁保持一致

## TypeScript / JavaScript

- 优先 `interface` 描述对象类型；避免 `any`，用 `unknown` + 断言
- 函数参数与返回值显式声明类型；`const` 优先
- 前端组件用函数组件 + Hooks，不用 class 组件
- Props 接口命名 `{ComponentName}Props`，放组件文件内或 `types/`
- 工具链：ESLint + Prettier

## Java

- 遵循《阿里巴巴 Java 开发手册》或 Google Java Style，团队二选一并统一
- 一个文件一个 public 类；优先组合而非继承
- 集合处理优先 Stream；资源使用 try-with-resources
- 工具链：Checkstyle / Spotless，纳入构建期校验

## Python

- 遵循 PEP 8；公共函数加类型注解
- 虚拟环境隔离依赖（venv / uv），锁文件入库
- f-string 格式化；禁止裸 `except:`，异常类型具体化
- 工具链：Ruff（lint + format 一体）或 Black + Flake8

## 样式（前端）

- 优先工具类（Tailwind）或组件级样式，避免全局样式污染
- 断点遵循框架默认，不自造断点

## 文件组织

- 导入顺序：标准库 / 框架 → 三方库 → 内部模块
- 同一目录下的文件使用相对路径导入
- 组件文件扩展名 `.tsx` / `.vue`，纯逻辑文件 `.ts` / `.py` / `.java`

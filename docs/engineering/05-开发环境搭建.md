# 开发环境搭建

> 与技术栈无关的通用流程；各运行时的版本管理与依赖隔离见对应小节。

## 运行时版本管理（推荐）

| 运行时 | 版本管理工具 | 安装示例 |
| --- | --- | --- |
| Node.js | nvm / fnm | `nvm install 20 && nvm use` |
| Python | pyenv + venv / uv | `pyenv install 3.12` |
| Java | SDKMAN! | `sdk install java 21-tem` |
| Go | 官方包 / goenv | — |

> 仓库根目录放版本锁定文件（`.nvmrc` / `.python-version` / `.sdkmanrc`），CI 与本地保持一致。

## 依赖隔离

| 技术栈 | 方式 | 常用命令 |
| --- | --- | --- |
| Node | node_modules + lockfile | `npm ci` / `pnpm i --frozen-lockfile` |
| Python | venv / uv | `python -m venv .venv && source .venv/bin/activate`；`uv sync` |
| Java | Maven / Gradle 托管 | `mvn spring-boot:run` / `./gradlew bootRun` |

## 启动约定

- 一条命令启动：根目录 `start.sh`（或 `Makefile`），完成依赖安装 + 启动
- 所有文档只引用该入口，避免 README、CI、脚本三处命令漂移

## 常用命令（按项目替换）

| 用途 | Node / 前端 | Python | Java |
| --- | --- | --- | --- |
| 启动开发服务 | `npm run dev` | `uvicorn main:app --reload` | `./gradlew bootRun` |
| 生产构建 | `npm run build` | `python -m build` | `mvn package` |
| 运行测试 | `npm test` | `pytest` | `mvn test` |

## 构建验证

- 本地执行一次生产构建，确认产物完整再提交
- 根目录如有验证脚本（如 `poc_verification.py`），提交前跑一遍

## 环境变量

- 集中根目录 `.env` 管理；提交 `.env.example`；`.env` 入 gitignore
- 代码中禁止硬编码密钥 / 主机 / 端口（见 `AGENTS.template.md` §0）

# 构建与部署

> 按项目形态选择对应小节。原则：**一条命令构建、一条命令部署、产物可追溯、回滚有预案**。
> 本仓库示例（静态托管到 GitHub Pages）的具体流水线见 `docs/Dev/部署过程记录.md` 与 `docs/Product/ARCH.md`。

## 构建产物

| 技术栈 | 构建命令 | 产物 |
| --- | --- | --- |
| 前端（Vite / webpack） | `npm run build` | `dist/` 静态文件 |
| Node 服务 | `tsc` 或直接运行 | `dist/` + lockfile / Docker 镜像 |
| Java | `mvn package` / `./gradlew bootJar` | jar / war |
| Python | `python -m build` / 直接运行 | wheel / Docker 镜像 |

## 部署形态

### A. 静态托管（纯前端 / SPA）

- 目标：GitHub Pages / Vercel / Netlify / 对象存储 + CDN
- 要点：CI 中注入 base 路径（如 `/<repo>/`）；构建 → 上传产物 → 发布

### B. 服务器部署（传统后端）

- systemd 托管进程 + nginx 反向代理
- 发布脚本封装：拉代码 → 构建 → 重启 → 健康检查 → 失败自动回滚

### C. 容器化（后端长期演进推荐）

- 多阶段 Dockerfile；本地用 Compose 编排依赖（DB / 缓存）
- 镜像 tag 用 commit SHA 或语义化版本，禁止只依赖 `latest`

### D. Serverless / 云函数

- 目标：云函数、边缘运行时
- 要点：关注冷启动与包体积；环境变量用平台 Secrets 注入

## CI/CD 通用步骤

```
1. checkout
2. 安装运行时（版本与本地锁定文件一致）
3. 安装依赖（用 lockfile，保证可复现）
4. 质量门禁：lint → 类型检查 → 测试（与本地命令完全一致）
5. 构建
6. 部署（上传产物 / 推镜像 / 触发发布）
```

- 触发：推送主干分支 + 手动触发（`workflow_dispatch`）
- 用 `concurrency` 取消重复构建，避免并发部署
- 多模块仓库用 `paths` 过滤触发范围，减少无效构建

## 回滚

- 保留上一版本产物 / 镜像，一条命令切回
- 数据库变更遵循向后兼容原则（先加后删），保证旧代码可跑

## 环境变量

- CI/CD 用平台 Secrets 注入同名变量；代码与日志禁止出现密钥

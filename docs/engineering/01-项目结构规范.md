# 项目结构规范

> 本规范与技术栈无关，适用于前端、后端（Node / Java / Python）等各类项目。各栈的典型结构见对应小节；本仓库示例项目的实际结构见 `docs/Product/ARCH.md`。

## 通用分层原则

```
入口层    ← 路由 / main / 启动类：只做组装与分发，不放业务逻辑
业务层    ← 核心逻辑（服务、用例、hooks）：与具体框架和协议解耦
数据层    ← 数据库 / 外部 API / 文件访问：统一封装，不掺业务判断
公共层    ← 类型定义、工具函数、常量：无状态，无业务概念
```

**依赖方向（硬约束）**：上层可引用下层，禁止反向引用；公共层不引用任何业务代码。

## 前端（React / Vue / Svelte）

```
src/
├── main.tsx / main.js        # 入口
├── pages/ (或 views/)        # 页面容器：组合组件、持有页面状态
├── components/               # 可复用 UI 组件：props 进出，不直接取数
├── hooks/ (或 composables/)  # 状态与逻辑复用：与 UI 渲染无关
├── services/ (或 api/)       # 后端接口封装：唯一网络出口
└── types/                    # 类型定义
```

## Node 后端（Express / Fastify / Nest）

```
src/
├── app.ts / main.ts          # 启动入口：中间件装配、路由挂载
├── routes/ (或 controllers/) # 接口层：参数校验 + 调用 service
├── services/                 # 业务逻辑
├── models/ (或 repositories/)# 数据访问
├── middlewares/              # 鉴权、日志、错误处理
└── config/                   # 配置读取（.env 唯一出口）
```

## Java（Spring Boot）

```
src/main/java/<pkg>/
├── Application.java          # 启动类
├── controller/               # REST 接口：参数校验 + 调用 service
├── service/                  # 业务逻辑（接口 + 实现）
├── repository/ (或 mapper/)  # 数据访问（JPA / MyBatis）
├── entity/ (或 domain/)      # 数据库实体
├── dto/                      # 接口传输对象，与 entity 隔离
└── config/                   # Bean 配置、安全配置
```

## Python（FastAPI / Django / Flask）

```
src/                         # Django 按 app 划分，原则相同
├── main.py                  # 入口
├── api/ (或 routers/)       # 接口层：Pydantic 校验
├── services/                # 业务逻辑
├── models/                  # ORM 模型
├── schemas/                 # 请求/响应结构体
└── core/ (或 config/)       # 配置与公共工具
```

## 通用约束

- 单一职责：每文件 / 每类一个主要功能
- 业务逻辑只写在业务层；入口层与数据层保持"薄"
- 公共工具不引入业务概念，保持可跨项目复制

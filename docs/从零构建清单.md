# 从零构建 — 信息文档清单与步骤

---

## 第一步：产品定义 → PRD.md

**核心问题：做什么？**

| 需要你提供的信息 | 产出文档 |
| --- | --- |
| 产品背景与目标 | 解决了什么问题、给谁用 |
| 功能清单 + 优先级 | P0/P1/P2 三级，定义 MVP 边界 |
| 用户故事 | 典型使用场景（如"收银台出示条形码"） |
| 成功指标 | 性能目标、体验指标 |
| 做/不做 | 明确项目边界 |

**产出方式：** 引导梳理需求，输出 PRD。

---

## 第二步：技术方案 → ARCH.md

**核心问题：怎么做？**

| 需要你提供的信息 | 产出文档 |
| --- | --- |
| 技术栈偏好（如有） | 框架、语言、工具链 |
| 部署目标 | 静态托管 / 服务器 / App |
| 特殊约束 | 离线可用、零成本、兼容性要求等 |

**产出方式：** 根据 PRD 给出技术选型建议和理由，输出架构文档。

---

## 第三步：工程规范 → engineering/

**核心问题：代码怎么写才规范？**

| 需要你提供的信息 | 产出文档 |
| --- | --- |
| 团队规模 | 单人还是多人协作 |
| 已有习惯（如有） | 编码风格、Git 工作流偏好 |

**产出方式：** 输出编码规范、命名规则、Git 工作流、项目结构标准。

---

## 第四步：项目脚手架

**核心问题：从哪里开始写代码？**

| 动作 | 说明 |
| --- | --- |
| 初始化项目 | `npm create vite` 或手动搭建 |
| 安装依赖 | React, Router, Tailwind 等 |
| 配置工具链 | TypeScript, Vite, Tailwind |
| 搭建目录结构 | 按 ARCH.md 规划的分层创建空目录 |

**产出方式：** 直接执行，生成可运行的骨架项目。

---

## 第五步：迭代实现

**核心问题：按什么顺序写功能？**

| 轮次 | 内容 |
| --- | --- |
| 第一轮 | P0 功能（上传 → 列表 → 大图展示） |
| 第二轮 | P1 功能（删除、编辑、屏幕常亮） |
| 第三轮 | P2 功能（搜索、排序、导出导入、PWA） |

**产出方式：** 逐轮实现，每轮完成后由你验收，再进入下一轮。

---

## 第六步：CI/CD 与部署

**核心问题：怎么上线？**

| 需要你提供的信息 | 产出 |
| --- | --- |
| 代码仓库地址 | GitHub / GitLab 等 |
| 托管平台偏好 | GitHub Pages / Vercel / Netlify |
| 域名（如有） | 自定义域名绑定 |

**产出方式：** 配置 CI/CD 流水线，完成自动部署。

---

## 总结：你需要提供的全部信息

| # | 信息 | 必要程度 |
| --- | --- | --- |
| 1 | 产品想解决什么问题 | ★★★★★ |
| 2 | 核心功能清单（哪些必须做） | ★★★★★ |
| 3 | 技术栈偏好（如有） | ★★★☆☆ |
| 4 | 部署目标 | ★★★☆☆ |
| 5 | 代码仓库地址 | ★★★☆☆（上线时需要） |
| 6 | 团队编码习惯（如有） | ★★☆☆☆ |

其余全部由 AI 辅助完成（需求梳理、技术选型、编码规范、脚手架搭建、功能实现、CI/CD 配置）。
